# Start with a local workspace

Verdlen begins with a simple rule: **personal work should remain useful on the device where you created it**. An account, a cloud subscription, and a collaboration membership are separate concerns.

## 1. Create work before signing in

Create a page and add a few blocks. A successful local durability receipt is different from a later cloud-sync receipt. The interface should not call a queued network request “saved”.

## 2. Choose synchronization deliberately

Signing in identifies an account. It should not silently redefine every local record as a cloud-owned cache. A synchronization enrollment can later select supported data categories and establish the remote authority needed for collaboration.

## 3. Keep an exit path

Backups and exports serve different purposes. Export produces portable user content. A recovery backup preserves the additional identities and relationships needed to restore supported Verdlen state.

## When team access changes

Team content is different from personal local content. If membership is revoked, the server denies new reads immediately on the supported online path. The client then locks and removes scoped cached/derived data according to the revocation contract.
